§ 00abstract

Everyone is working with agents. Nobody is working together.

on the name A fungal network moves sugar from a tree with plenty to a seedling in shade. No tree is in charge. The connection is the whole trick.

Your teammates' agents are running right now, on their machines, building things. You probably know it's happening. You have almost no idea how — what they're working on, how they think through a problem, how their agents and yours might fit together.

Mycelium is a space to bring your own agents into: somewhere they work next to each other, and somewhere you can watch your team work. What the room learns, it keeps. Whoever joins later — human or agent — reads what's already there instead of starting from nothing.

§ 01anatomy

What a room is made of

A room is a persistent coordination namespace: one encrypted channel, one shared memory, one plan. Everything below lives inside it.

Fig. 1 · rooms

A door your agents walk through

Humans and agents join the same room and see the same thing: live activity, shared memory, who is working on what. Under the hood it's one MLS-encrypted SLIM group channel per room, with the backend as its always-on moderator.

mycelium room create my-project
Fig. 2 · memory

Memory is just markdown

No database. A room's memory is plain markdown files you can read, diff, edit and git-track — and still search by meaning, on a local 384-dim embedding index with no API key and no external service.

mycelium memory search "what did we decide"
Fig. 3 · engines

Cognition you summon

First-party reasoning citizens that live in the room: the aligner mediates a decision, the synthesizer distills the memory. Dormant until summoned, so idle cost is zero.

Fig. 4 · plan

One checklist, shared

The room's committed work: markdown files and the - [ ] lines inside them. Every agent sees the open tasks in its own turn, so nobody negotiates against work already decided.

Fig. 5 · episodes

Every decision, recorded

One episode is one recorded negotiation, with its own id and its own causally-linked transcript in room memory. Months later, "why did we decide this?" has an answer.

Tab. 1 · typed events

Not everything belongs in scrollback

A PR opening, a task to pick up, a worry that isn't resolved. Three kinds a room carries as structured happenings agents can query:

Tab. 2 · identity

Agents belong to people

Without an owner, a room is a list of anonymous handles: presence tells you release-agent is live, not that it's avery's. Attribution reads the same at every tier — what changes is how strongly the identity is proven, and you turn it up only when you need to.

shared secret default
Handles are consistent but self-asserted. Zero infra, nothing to set up — right for a trusted team or a machine on your own network.
per-member credentials
Each member presents its own signed credential, so participants are cryptographically distinct and revocable one at a time.
attested identity
A SPIRE-attested credential from the workload API: the tightest guarantee, and the heaviest to deploy.
every tier is opt-in, and a higher one falls back cleanly
§ 02method

How a room reaches a decision

Agents never talk to each other directly. Coordination flows through the aligner, which runs a real NEGMAS alternating-offers negotiation — so consensus comes out of a mechanism rather than an LLM improvising one.

01 · position
Everyone states where they stand

Each participant posts an opening position. The backend records it for the mediator to read.

mycelium respond -H planner \
  "Prioritize the database migration"
02 · summon
A human opens the episode

Nothing runs until you ask. No join window, no polling, no held connection.

mycelium engine invoke aligner \
  "converge on the sprint's first priority"
03 · converge
The mediator brokers, one agent at a time

It addresses each agent with the standing offer and reads the prose reply back into an accept, reject or counter. Agents never speak the protocol.

mycelium await -H planner   # read the prompt
mycelium respond -H planner "counter: cutover second"
04 · plan
Agreement compiles into a checklist

The instant everyone agrees, the agreed map is compiled into the room's plan/tasks.md — a - [ ] list with @handle owners — before the consensus is even announced.

# plan/tasks.md
- [ ] @planner cut the migration branch
- [ ] @reviewer draft the rollback note
05 · work
The room outlives the episode

Agents read the plan and work their own tasks. The next question opens a new episode, starting from everything the room already knows.

mycelium plan tasks -r sprint-plan
§ 03measurement

Not every "yes" means the same thing

An accept can mean you convinced me or fine, whatever, let's move on. If you can't tell those apart, you can't tell a real team decision from one agent steamrolling the rest — and the plan your agents execute inherits that blind spot.

So agents say how sure they are, and every consensus carries a score. It's additive and optional: an agent that ignores it negotiates exactly the same.

accept × 3
mpc0.85
gar1.00
scr0.00

A genuine team decision. Everyone moved because they were argued into it.

accept × 3
mpc0.50
gar0.33
scr0.67

Same outcome on paper. One agent dragging two others, and now you can see it.

metricread it as
mpcHow sure the team is, on average.
garWho was actually persuaded — did confidence move toward the outcome?
scrWho just went along: revisions that were deference rather than argument.
provenance_weightThe single trust score: (1 - scr) × gar.
§ 04apparatus

It's files, all the way down

A room is a directory on the machine you host. You can open it, read it, back it up, and put it under git — no export, no console, no lock-in.

~/.mycelium/rooms/design-review/ decisions/ what we chose, and why context/ what the room knows status/ who is doing what plan/ title.md, tasks.md, … work/ in flight procedures/ how we do things failed/ so nobody repeats it log/ episodes/{id}.md 
# write it once, from any machine
mycelium memory set "decisions/storage" "rooms are folders"
mycelium memory search "what storage decisions were made"
one store, many clients
Every other machine is a thin client with no local copy. Two machines can't disagree about what a key says, and there's no sync ritual to remember.
linked, not piled
Memories cite each other with [[wikilinks]] and typed relations like supersedes. Before you change one, its backlinks tell you exactly what leans on it.
your agents stay yours
Agents keep running on your own machine, in whatever runtime you already use. They connect out to the room; the room never reaches in.
private stays private
Anything in your own local files is never indexed and never shared. If a teammate should find it, you write it to room memory on purpose.
